# GitHub Themes — 实现思路与技术路线

> 本文档描述 **GitHub Themes** 用户脚本的设计思路与关键技术路线，依据 `GithubTheme.js`（@version 1.4.0.0）真实实现整理。
>
> 与 `MAP.md` 的分工：`MAP.md` 是**代码地图**（模块/函数/行号的精确索引）；本文是**思路与决策**（为什么这样设计、各条路线如何取舍）。两者互补，代码细节以 `MAP.md` 为准。

## 1. 项目定位

一个**自包含单文件**的 Tampermonkey / ScriptCat 用户脚本，为 `github.com` 全站提供 23 套手工打磨主题（11 浅 + 12 深 + 1 个「GitHub Default」还原项），并附带两个页面增强功能。

核心约束决定了整体架构：

| 约束 | 应对 |
| --- | --- |
| 单文件自包含，无构建步骤 | 主题数据 + 引擎 + UI 全部内聚于一个 IIFE |
| `document-start` 尽早介入 | `init()` 挂 `DOMContentLoaded`，DOM 就绪才注入，避免与 GitHub 动态样式竞争 |
| 覆盖 GitHub 全站组件（React 动态渲染） | 放弃逐选择器覆写，改用 **CSS 变量（Primer 体系）全覆盖**，动态内容经继承自动变色 |
| 浏览器前进/后退（bfcache）主题不失效 | 样式用 `<style>` **DOM 元素**注入而非 inline style，bfcache 随 DOM 存活 |
| 与 GitHub 原生样式长期共存 | 全部声明批量追加 `!important` |

## 2. 为什么是「CSS 变量覆盖」而不是「逐选择器覆写」

GitHub 的样式体系基于 Primer 的 CSS 变量（`--bgColor-default`、`--fgColor-accent`…），几乎所有组件都从 `:root` 变量取值。早期思路（见本文档历史版本）是精确定位 `.blob-code`、`.btn-*` 等类逐个覆写，但它有两个硬伤：

1. **覆盖不完整**：GitHub 组件成千上万，逐类穷举必然漏；
2. **不抗动态渲染**：React 新挂载的节点若带内联样式或新类名，旧选择器立即失效。

因此采用**变量级覆写**：只要把 `:root` 里 Primer 的 CSS 变量全部替换成主题色值，全站组件（无论何时渲染）都会经 `var()` 继承自动换色——一条规则都不需要写组件选择器。

```js
// 思路示意（非真实代码）
:root {
  --bgColor-default: #0d1117;
  --fgColor-accent:  #58a6ff;
  /* ... 共 402 条 ... */
}
```

代价是必须把 Primer 体系变量**补全**，否则未覆盖的变量仍取 GitHub 原生值，页面会「半旧半新」。这正是引擎要做的事。

## 3. 主题建模：语义 Token → 全量变量

每套主题只声明 **18 个语义 Token**（6 行 × 3 字段）：

- **背景层**：`bgDefault` / `bgSubtle`（卡片）/ `bgInset`（输入框、代码区）/ `bgEmphasis`
- **前景文本**：`fgDefault` / `fgMuted` / `fgSubtle` / `fgOnEmphasis`
- **语义色**：`accent` / `success` / `danger` / `warning` / `done`
- **组件色**：`headerBg` / `headerFg` / `codeBg` / `border` / `link`

主题作者只需回答「这 18 个语义值是什么颜色」，其余全部交给引擎推导。

### 引擎做的事（`generateCSSVariables`）

1. **派生衍生态**：语义色的 `hover`（提亮/压暗 12%）、`active`（18%）与半透明族 `-subtle`（α 0.12）/`-muted`（α 0.30）；边框 `muted`（α 0.55）/`subtle`（α 0.35）；按钮与控件 hover/active 的亮度偏移（±4/±8，按主题深浅取方向）；阴影、overlay 等。
2. **输出完整 `:root` 块**：402 条 Primer CSS 变量，按 46 个注释小节组织（核心背景/文本、语义色、边框全族、Header、卡片、CodeMirror、Prettylights 语法高亮、按钮 7 态族、表单控件、Overlay/菜单/Tooltip、Label、Diff、贡献图、ANSI 终端色等），覆盖 GitHub Primer 组件体系。
3. **批量加固**：模板字符串经正则把每条 `--var: value;` 统一追加 `!important`，确保压过 GitHub 动态样式。

### 颜色工具三件套

| 工具 | 作用 |
| --- | --- |
| `hexToRgba(hex, alpha)` | 转半透明色 |
| `lightenOrDarken(bg, color, amount)` | 依**背景亮度**决定提亮或压暗（暗底 `1+amount`、亮底 `1-amount`），做出「更强烈」的 hover 感 |
| `adjustBrightness(hex, amount)` | 加减固定亮度（按钮 hover/active） |

### 加主题 = 零逻辑改动

新增一套主题只需在 `themes` 配置里复制一个块、替换 18 个 Token 值。脚本自动完成派生、变量生成与 UI 列表接入。`themes` 共 24 项 = 23 套真实主题 + `default`（`tokens: null` + `isDefault: true`，语义是「不注入任何样式 → 还原原生」）。

## 4. 注入与还原：`applyTheme`

```text
移除旧 #github-theme-style
  → default / tokens 为空 ? 直接 return（恢复原生，不留痕迹）
  → 否则 generateCSSVariables(tokens) → 新建 <style id="github-theme-style"> 注入 <head>
```

关键决策：**用 `<style>` DOM 元素而不是 inline style**。bfcache 会缓存整棵 DOM，`<style>` 元素随页面存活；即便个别情况被清，`pageshow(e.persisted)` 还会兜底重建一次。切换主题只替换这一个元素，全站即时换色。

## 5. 增强功能一：列表行悬停（纯 CSS，零 JS 状态）

独立的 `<style id="github-boxrow-style">`，与主题样式分离，默认开启、可独立开关：

- `.Box-row` 强制直角（`border-radius: 0`）；
- `:hover` → 淡色底 + 左侧竖条（`box-shadow: inset Npx 0 0 …`，N 为滑杆粗细 2–16px），链接与自绘下载按钮跟随主题强调色；
- **与主题联动**：竖条/底色引用的不是写死的颜色，而是主题注入的 `--ghb-accent-bar` / `--ghb-boxrow-hover-bg` 两个变量 → 切主题自动变色，**无需重建本 style**；「GitHub Default」主题下走 CSS 兜底（原生蓝）。

纯 CSS 意味着没有观察者、没有状态管理，关闭开关 = 移除 style 元素 = 彻底还原。

## 6. 增强功能二：Release 分组排序（DOM 重排，默认关闭）

这是唯一需要操作 DOM、因此唯一需要 MutationObserver 的功能。

### 平台判定（`detectPlatform`）

从下载链接 `href` 的 basename（优先，已 `decodeURIComponent`）或行文本判定系统，按扩展名/关键词优先级：

```text
.apk/.aab/android → android    .ipa/ios → ios
.exe/.msi/win*/mingw → windows  .dmg/.pkg/macos/osx/darwin → mac
.appimage/.deb/.rpm/.snap/linux/ubuntu → linux   未命中 → other（垫底）
```

### 排序与还原

- 只取含 `.octicon-package` 的 `.Box-row`，**按父容器分组**（`byParent` Map）逐组处理，绝不误动页面其它列表；
- 顺序按 `PLATFORM_ORDER = [windows, mac, linux, android, ios]`，同系统保持原始相对序；
- **可还原性**：首次见到某行记录 `dataset.ghbOrig`（原始相对序，单调计数器防碰撞）——关闭开关按 `ghbOrig` 归位；反复开关不产生漂移；
- **幂等防死循环**：先构造目标子序列并与当前 `children` 对比，**顺序没变就完全不动 DOM**——这是 MutationObserver 方案不自循环的关键。

### 图标着色（`colorReleaseIcon`）

同系统 `.octicon-package` 图标统一色（Windows 蓝 / mac 银灰 / linux 橙 / android 绿 / ios 靛紫），以 `!important` 内联 `color` 覆写 Primer 的 `color-fg-muted`；关闭/未命中则移除，还原原生灰。

### 观察者（唯一的 observer）

监听 `document.documentElement` 的 `childList + subtree`，**回调第一件事查 GM 开关，关闭即返回**；GitHub 异步渲染/路由切换触发后 300ms 防抖执行一次。与 boxrow（纯 CSS）不同，Release 分组必须在 React 渲染出资产行之后才能操作 DOM，因此需要此观察者。

## 7. 增强功能三：Release 资产类型提示（DOM 装饰，默认开启）

GitHub Release 页面常把 20+ 个资产平铺（安装包、压缩包、校验和、签名、SBOM、调试符号、更新元数据……），文件名是唯一的线索，普通用户很难判断「哪个能装、哪个不用管」。本功能在每行资产后追加一个小徽章，用动词短语回答「我该怎么用」，悬浮再补「是什么 / 给谁 / 怎么装 / 替代选择」。

### 7.1 分类维度

| 维度 | 例子 | 决定什么 |
| --- | --- | --- |
| 目标系统 | `windows` / `mac` / `linux` / `android` / `ios` | 本机 ⭐ 推荐与图标配色 |
| CPU 架构 | `x86_64`、`aarch64/arm64`、`universal2`、`i686` | 同系统内优先 64 位 / 通用包 |
| 分发形态 | 安装器 / 免安装压缩包 / 包管理器格式 | 徽章文案（`安装版` / `免安装`） |
| 安全与工程元数据 | 校验和 / 签名 / SBOM / 来源证明 / 调试符号 / 更新元数据 | 弱化为「只给图标」，默认不打扰 |
| 渠道 | nightly / beta / debug / lite | 备注在悬浮里说明 |

### 7.3 设计决策

- **只做弱推断，不硬猜**：识别不出来就不加徽章、不标 ⭐——错误推荐比没有推荐伤害更大。
- **内联与悬浮分工**：内联徽章必须短（动词短语解释「怎么用」）；「是什么 / 给谁用 / 替代选择」放悬浮，避免行宽爆炸。
- **不依赖 hover**：触屏与键盘用户通过 `focusin` / 点击也能打开浮层；`Escape` 关闭。
- **浮层挂 `body` + `position:fixed`**：资产行在 `.Box` 内，祖先 `overflow` 可能裁切；`fixed` 定位加滚动 / 缩放时关闭，规避错位。
- **元数据只给图标**：校验和 / SBOM 等对多数用户是噪音，但需要的人一眼能认，所以保留可发现性、弱化存在感。
- **安装包还要再分「能不能装」**：`.msixupload/.appxupload` 只用于商店上架，归入元数据并排除在 ⭐ 之外；`.msixbundle` 才是用户该下的那个。
- **色彩语义化**：每条规则带 `tone`，徽章与浮层共用 `--ghb-*`（随明暗主题自动换色）；压缩包一旦识别出系统就换成「📦 免安装」并走 portable 色，与普通压缩包区分。
- **带版本点号的安装器**：`setup-1.2.3.exe`、`ffmpeg_setup_v6.1.exe` 必须照样命中 `win-installer`，正则允许分隔符后继续出现点号与数字。
- **与分组互补**：分组（增强二）重排 DOM、默认关闭；提示（增强三）只加内容、不改顺序，默认开启。两者可独立开关。

## 8. 交互层：ThemePanel 单例

- **生命周期**：懒创建——首次打开面板才建 DOM 并插入 body；`toggle()` ↔ `show()/hide()`（切 `.show` 类）；打开后 100ms 自动聚焦搜索框。
- **面板结构**：头部（标题 + 主题计数 + 搜索框 + 关闭）；内容区三段——浅色网格 / 深色网格（含空状态）+「📐 列表行增强」控件（开关 + 滑杆 + 实时值）+「🗂️ Release 分组排序」开关；底部（当前主题 + 恢复默认 + 快捷键提示）。
- **渲染**：`default` 恒排最前；default/浅色入 lightGrid、深色入 darkGrid；搜索词匹配显示名或 key；某区过滤为空则隐藏该区并显示空状态；按钮卡片带主题色**渐变预览**（`linear-gradient(135deg, bgDefault, bgSubtle, accent)`）。
- **切换**：写 GM → 更新内存镜像与按钮 `.active` → 更新底部当前主题 → `applyTheme` → toast。
- **搜索防抖**：200ms；`ESC` 语义分级——有搜索词先清词恢复全列表并 `stopPropagation`，无词则冒泡让 document 关闭面板。
- **关闭路径**：× 按钮 / 面板外点击 / `ESC`。

## 9. 状态与持久化

4 个 GM 存储键，改动即时持久化；除 `github_theme` 在 `ThemePanel` 实例维护镜像外，其余两个增强函数**每次执行实时读 GM**，保证面板 / init / observer 任意入口状态一致。

| 存储键 | 默认 | 用途 |
| --- | --- | --- |
| `github_theme` | `default` | 当前主题 |
| `github_boxrow_enabled` | `true` | 列表行增强开关 |
| `github_boxrow_bar_width` | `4` | 竖条粗细（2–16） |
| `github_release_group_enabled` | `false` | Release 分组开关（opt-in） |

## 10. 运行时事件全景

| 事件 | 处理 |
| --- | --- |
| `DOMContentLoaded` | `init()`：注入动画 → boxrow → Release 分组 + 挂 observer → 恢复主题 → 注册菜单/快捷键 |
| `document keydown` | `Ctrl+Shift+T` 面板；`Ctrl+Shift+←/→` 环形切主题 |
| 面板控件 `change`/`input` | 写 GM → 即时重应用（boxrow 重绘 / Release 重排） |
| `pageshow (persisted)` | bfcache 兜底：重应用主题 + Release 分组 |
| MutationObserver | 仅 Release 开启时生效，300ms 防抖重排（幂等） |

## 11. 与同类 GitHub 主题脚本的思路差异

多数 GitHub 主题脚本用「一个大 MutationObserver 全站分流」来等组件出现后再改样式。本脚本因走 **CSS 变量继承**路线，动态内容天然带主题色，所以**不需要全站观察者**——观察者只服务于必须改 DOM 结构的 Release 分组这一个场景，复杂度被严格限制在它该在的地方。

## 12. 技术债与后续方向

- **主题创作工具**：18 个 Token 虽少，手工配色仍靠肉眼调。规划一个 HTML 可视化工具：调 Token → 实时预览 → 一键生成配置块（开发中）。
- **变量补全维护**：Primer 体系在演进，若 GitHub 新增 CSS 变量，需在 `generateCSSVariables` 中补条目，否则新组件回落到原生色。
- **版本节奏**：增强功能与主题新增分开 bump（`1.4.0.0` 新增 Release 资产类型提示；`1.3.0.0` 已纳入行悬停与分组两大增强）。
